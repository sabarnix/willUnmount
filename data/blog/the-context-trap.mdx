# From Small Fixes to Big Architecture: Lessons in Skill Context Optimisation

Two years ago, I started using AI IDEs like Cursor for small, contained problems. It was a neat trick: I’d paste a function, ask for a tweak, and get a result. Simple.

A year later, I was using it for full sprint tasks. I felt productive, but I was also spending half my day reviewing the AI’s output, tweaking its logic, and questioning if it actually understood the architecture. The trust wasn't there yet.

Today, I can hand over most high-level tasks. The difference hasn't just been in the model's capabilities—it’s been in how I provide context.

### The Context Trap

I learned this the hard way. I kept adding more "stuff" into the AI’s rules and `.mdc` files, component patterns, and API docs. I thought, *if I just give it more context, it’ll be smarter.* 

It wasn't.

It started acting up. It would hallucinate patterns that didn't exist or get bogged down in outdated versions of our component library. I kept ignoring the context token counter. I just kept pushing more data in, assuming "more = better."

The real problem was that I was forcing the AI to process the *whole* file or directory every time I asked a question. It was drowning in information. It wasn't being lazy; it was being overwhelmed by noise. 

![The Context Trap](/static/images/context-trap.png)

### The "50% Rule"

I realized that AI works best when the context window is used for strict relevance, not for dumping a whole library. You don't need to give it everything. You need to give it *just enough* to anchor it to the problem at hand.

When I started building a new skill rule for our component library, I stopped dumping every single component file into the context. Instead, I created a focused definition: just the interface signatures, the usage patterns, and the "why." 

Once I stopped overfeeding it, the results became significantly sharper.

### Why This Matters

We often blame the model when things go wrong, but usually, it's our input that’s the bottleneck. If your AI agent is giving you generic, shallow answers, look at what you’re feeding it. Are you dumping 20 files into the chat? Are you giving it legacy code alongside new architecture? 

Trust isn't just about the model getting better. It's about you becoming a better editor of the context you provide.

The goal is to get the model to a place where it understands your intent without being forced to sift through a haystack. When you get that balance right, it finally feels like you're working with a second brain, rather than a glorified copy-paste machine.

![Clean Context Optimisation](/static/images/clean-context.png)

Moving from dumping context to *optimising* it was the quiet revolution in my workflow. Maybe it’s time you checked your context window, too.
